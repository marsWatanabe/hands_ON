## 6. 確認で分かったこと

| 内容 | 扱い |
| --- | --- |
| 画面の幅が 1600px 未満だと、在庫センター管理の一覧の操作列（編集・削除）が見えない（部品在庫は 1440px 未満、製品在庫は 1536px 未満でも横スクロール） | UI の改修で対応する（レビュー報告書 FM-1） |
| 開発サーバーの起動直後の初回アクセスで、画面の部品の読み込みに失敗することがある（再読み込みで直る） | 開発時のみ。本番ビルドでは起きない（FL-3） |
| 競合などで DB の制約に負けたときのエラーは、共通のメッセージになる | `error.details` を決めてから対応する（FM-2） |

## 7. 制限

- 同時操作（複数ユーザーが同じデータを編集）は、画面からは確認していない。同時登録の重複と、カテゴリの削除と在庫登録の競合は、バックエンドの統合テスト（`ConcurrencyIntegrationTest`）で確認している。
- PostgreSQL では、SQL（V1〜V5）とロックの動きだけを確認している。アプリ全体を PostgreSQL で動かす確認は未実施（HANDOFF 7.2）。
- E2E テストは CI では実行していない（ローカルのみ）。
