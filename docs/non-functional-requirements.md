## 3. 運用・保守性（NFR-OPS）

| ID | 項目 | 現状の根拠 | 目標値 [提案] | 状況 |
| --- | --- | --- | --- | --- |
| NFR-OPS-01 | ログ | `logging.level.org.springframework=DEBUG`、`spring.jpa.show-sql=true` [実装 `application.properties`] | 本番は INFO。SQL ログを無効。リクエスト ID を付ける。**個人情報（氏名、メール、電話番号）、パスワード、トークンを出さない** [原典 copilot-instructions] | × |
| NFR-OPS-02 | 監視 | `/actuator/**` を認証なしで許可 [実装 `SecurityConfig`]。Actuator の依存は `pom.xml` に無い | ヘルスチェック（死活）、エラー率、応答時間を監視。監視用エンドポイントは内部ネットワークか認証付きに限る | × |
| NFR-OPS-03 | 監査・操作履歴 | サイドバーに「操作履歴一覧」のみ。仕様とテーブルは無い | 誰が、いつ、何を変更したかを記録する。保存期間は要確認（Q-6） | ？ |
| NFR-OPS-04 | 設定の分離 | `application.properties` に H2 のパスワード `password` などを直書き [実装] | 環境ごとにプロファイルを分け、秘密情報は環境変数やシークレット管理から読む | × |
| NFR-OPS-05 | API ドキュメント | SpringDoc（OpenAPI）で自動生成 [原典 ADR-0004] | 本番では Swagger UI を無効、または認証付きにする | △ |
| NFR-OPS-06 | コード規約 | Google Java Style、ESLint、Javadoc と JSDoc を日本語で記述 [原典] | 規約に沿う。CI で検査する | △ |
| NFR-OPS-07 | ビルドの品質ゲート | フロントの `next.config.mjs` が `typescript.ignoreBuildErrors: true`、`eslint.ignoreDuringBuilds: true` [実装] | 型エラー、lint エラーでビルドを失敗させる | × |
| NFR-OPS-08 | 依存の更新 | 記載なし | 依存ライブラリの脆弱性を定期的に確認し、更新する | ？ |
| NFR-OPS-09 | リリース | 記載なし。PR テンプレートあり（日本語、開発内容、実装方法、仕様、確認事項）[原典] | PR 単位でレビューし、テスト通過を必須にする | △ |

| NFR-MIG-05 | データ移行 | 既存システムからの移行の記載なし | 既存データの有無を確認する（Excel などからの CSV 取り込みの要否） | ？ |

## 5. セキュリティ（NFR-SEC）

| ID | 項目 | 現状の根拠 | 目標値 [提案] | 状況 |
| --- | --- | --- | --- | --- |
| NFR-SEC-01 | 認証 | JWT（RS256）、パスワードは BCrypt [原典、実装] | 維持する | ○ |
| NFR-SEC-02 | トークンの有効期限 | アクセス 24 時間、リフレッシュ 7 日 [実装]。ADR-0002 は「失効管理や短い有効期限が必須」と明記 | アクセスは 15 分程度、リフレッシュは 7 日以内。リフレッシュトークンの失効（ログアウト、無効化）を設計する | △（hands_ON は 15 分、失効は未実装） |
| NFR-SEC-03 | トークンの保管（画面） | JavaScript から Cookie に保存。コードに「FIXME」あり [実装 `AuthContext.tsx`] | HttpOnly、Secure、SameSite を指定した Cookie か、BFF 方式にする | × |
| NFR-SEC-04 | 認可 | USER 権限以上 [原典 API]。ADMIN との差は未定義 | 権限表を確定する（要件定義 3.3、Q-2） | ？ |
| NFR-SEC-05 | アカウント登録 | 誰でも自己登録でき、USER 権限を得る [実装] | 本番では、管理者による登録か承認制にするかを決める（Q-1） | ？ |
| NFR-SEC-06 | 総当たり対策 | 記載なし | ログイン失敗の回数制限、ロック、通知 | × |
| NFR-SEC-07 | パスワード方針 | 記載なし | 8 文字以上（hands_ON は 8〜72 文字）。漏えいパスワードの確認や複雑さの規則は要確認 | △ |
| NFR-SEC-08 | 入力検証 | 桁数、形式の検証。XSS、SQL インジェクション対策 [原典] | `@Valid` による検証と、JPA のパラメータ化クエリを維持する。ソート項目は許可リストで検証する | ○ |
| NFR-SEC-09 | 個人情報 | 氏名、メール、管理者名、電話番号を扱う | ログに出さない。保存期間と削除の方針を決める。レスポンスにパスワードのハッシュを含めない（原典の登録、ログイン応答は `User` をそのまま返す） | △ |
| NFR-SEC-10 | 通信 | 記載なし | 本番は HTTPS のみ。HSTS を有効にする | ？ |
| NFR-SEC-11 | 開発用機能の閉鎖 | `/h2-console/**`、`/actuator/**` が認証なしで許可 [実装] | 本番では無効にする | × |
| NFR-SEC-12 | 鍵管理 | RSA 鍵を使用 [実装]。hands_ON は起動ごとに自動生成 | 本番は PEM ファイルかシークレット管理で固定し、定期的に更新する | △ |
| NFR-SEC-13 | CORS | 画面は Next.js の `rewrites` で API を同一オリジンとして呼ぶ [実装 `next.config.mjs`] | 画面からバックエンドを直接呼ぶ構成にする場合のみ、許可オリジンを設定する | ○（現構成では不要） |
| NFR-SEC-14 | 同時更新 | 在庫データは整合性最優先 [原典 copilot-instructions] | 楽観ロックで更新の消失を防ぐ（`version` 列。要承認） | × |
| NFR-SEC-15 | 脆弱性対応 | 記載なし | OWASP Top 10 を設計・レビューの観点にする | ○（レビュー観点に含める） |

## 9. 優先して対応する項目（提案）

本番に出す前の必須事項を先に並べる。

| 優先度 | 項目 | 関連 ID |
| --- | --- | --- |
| 高 | 開発用機能の閉鎖（H2 コンソール、Actuator、Swagger）、ログの設定、秘密情報の分離 | NFR-SEC-11、NFR-OPS-01、02、04、05 |
| 高 | アカウント登録方針とトークンの管理（有効期限、失効、画面側の保管） | NFR-SEC-02、03、05、Q-1 |
| 高 | スキーマ管理を Flyway に一本化し、PostgreSQL で検証 | NFR-MIG-01〜04 |
| 高 | バックアップと復旧手順 | NFR-AVL-04、05 |
| 中 | 同時更新対策、操作履歴 | NFR-SEC-14、NFR-OPS-03 |
| 中 | ユニットテストの整備、フロントのビルドの品質ゲート | NFR-QLT-01、NFR-OPS-07 |
| 低 | 検索の高速化、冗長化 | NFR-PRF-05、NFR-AVL-06 |
