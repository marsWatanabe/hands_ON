- ブラウザからの API 呼び出しは同一オリジン（`/api/...`）で行い、`next.config.mjs` の `rewrites` が `BACKEND_API_URL`（既定 `http://localhost:8080`）へ転送する。このため CORS の設定は要らない。
- ロジック（住所の分割、入力検証、API 呼び出し、トークンの更新）は `lib/` の純粋な関数にし、単体テストできるようにしている。

## 3. 在庫センター管理画面の仕様

### 3.1 一覧

| 列 | 内容 | 並び替え |
| --- | --- | --- |
| センター名 | `centerName` | 可 |
| 住所（都道府県・市区町村） | `address` を第 4 章の規則で分け、都道府県と市区町村までを表示する。判定できないときは全体 | 可（`address`） |
| 電話番号 | `phoneNumber` | 不可 |
| 管理者名 | `managerName` | 不可 |
| 稼働状況 | 稼働中 / 稼働停止（バッジ） | 可 |
| 最大保管容量（㎥） | 3 桁区切り。未設定は `-` | 可 |
| 現在保管容量（㎥） | 同上 | 可 |
| 操作 | 編集、削除 | — |

- 初期の並びは `centerId` の降順（API の既定。要件 C-9）。見出しをクリックすると昇順、もう一度で降順。`aria-sort` を付ける。
- 稼働状況の列は、画面仕様には無いが、検索条件の確認に必要なので追加した。
- 検索: センター名（20 文字まで）、住所（100 文字まで）、稼働状況（すべて / 稼働中 / 稼働停止）。検索ボタンで 1 ページ目から検索し直す。「クリア」で条件を空にして検索し直す。
- ページ送り: 「全 N 件（x / y ページ）」、前へ・次へ、1 ページの件数（10、20、50。API の上限は 100）。
- 0 件のときは「条件に一致する在庫センターがありません。」を表示する。最後のページの最後の 1 件を削除して空になったときは、1 つ前のページへ戻る。
- 取得に失敗したときは、画面上部にエラーと「再読み込み」を表示する。

### 3.2 新規登録・編集（モーダル）

| 項目 | 入力 | 必須 |
| --- | --- | --- |
| 在庫センター名 | 文字入力（20 文字まで） | 必須 |
| 郵便番号 | `123-4567` | 必須 |
| 都道府県 | 選択（47 件） | 必須 |
| 市区町村、番地・建物名 | 文字入力 | どちらか一方があればよい |
| 電話番号 | `03-1234-5678` | 必須 |
| 管理者名 | 文字入力（100 文字まで） | 必須 |
| 稼働状況 | 稼働中 / 稼働停止 | 必須（既定は稼働中） |
| 最大保管容量、現在保管容量（㎥） | 0 以上の整数 | 任意 |
| 備考 | 複数行（255 文字まで） | 任意 |

- 送信前に Zod で検証し、項目ごとにエラーを表示する。入力し直した項目のエラーは消える。
- サーバーのエラーは、409（センター名の重複）は名前の欄に、400 でメッセージが項目名で始まるものはその項目に、それ以外はモーダル上部に表示する。404（編集中に他で削除された）はモーダル上部に表示する。
- 成功したらモーダルを閉じ、トースト（登録しました / 更新しました）を表示し、一覧を取り直す。

### 3.3 削除

確認ダイアログ（センター名を表示）で「削除」を押すと論理削除する。すでに削除されていた（404）ときは成功として扱い、一覧から消す。それ以外の失敗はトーストで通知する。

## 4. 住所の扱い（要件 C-4）

DB と API は `address` 1 列（255 文字まで）のまま変えない。画面だけで分けて入力させる。

- 送信: 都道府県 + 市区町村 + 番地 を区切りなしで結合する（例: `大阪府` + `大阪市北区` + `梅田1-1-1` → `大阪府大阪市北区梅田1-1-1`）。
- 編集時の分割（`lib/address.ts` の `splitAddress`）:
  1. 先頭が 47 都道府県のどれかなら都道府県とする。
  2. 残りの先頭から、最初の「市・区・町・村・郡」までを市区町村とする。
  3. 「四日市市」「大町市」のように名前の途中で一致した場合は、続く市町村までを含める。
  4. 「市」の直後に「〇〇区」が続く場合（政令指定都市）は、区までを含める。
  5. 「郡」の直後に町村が続く場合は、町村までを含める。
  6. 判定できなかった部分は番地に残す。
- 分割は表示と入力の補助であり、結合すると元の文字列に戻る。判定を誤っても、ユーザーが 3 項目を直せばよい。分割できない既存データ（例: `大阪府テスト倉庫`）は、市区町村が空、番地に残りが入り、そのまま保存できる。
- 既知の限界: 「市」「町」を名前に含む地名で、規則 3〜5 に当てはまらないものは誤分割する。本格的に分けるには、列を分ける（スキーマと API の変更。要承認）か、住所の辞書を使う。

## 5. 入力検証

規則と文言は、バックエンドの `CenterRequest` と同じにしている（`lib/center-form.ts`）。サーバー側の検証は必ず行われるため、画面の検証は利便性のためである。

- 前後の空白は除いて送る。
- `<` と `>` は、センター名、市区町村、番地、管理者名、備考で使えない（サーバーも拒否する）。
- 現在保管容量は最大保管容量以下（両方が入力されているときだけ比べる）。
- 容量の上限は 999,999,999。

## 6. 認証とトークン

- `POST /api/v1/auth/authenticate` と `register` のレスポンス（`accessToken`、`refreshToken`、`user`）を Cookie に保存する（`lib/auth-storage.ts`）。属性は `SameSite=Strict`、HTTPS のときは `Secure`。保持期間は、アクセストークンが 1 日、リフレッシュトークンとユーザー情報が 7 日（ブラウザ側の保持。サーバー側の有効期限とは別）。
- API 呼び出し（`lib/api-client.ts`）は `Authorization: Bearer <accessToken>` を付ける。401 のときは、リフレッシュトークンで `POST /api/v1/auth/refresh-token` を 1 回だけ呼び、新しいトークンで再試行する。同時に複数の呼び出しが 401 になっても、更新は 1 回にまとめる。更新にも失敗したら、保存した認証情報を消し、`ProtectedRoute` が `/login` へ移動する。
- 403 はセッションを維持し、権限エラーとして表示する。現状は USER と ADMIN に操作の差は無い（保留中の Q-2）。

## 7. 既知の制限と未対応

- **トークンを JavaScript から読める Cookie に保存している**（原典の実装を踏襲。`NFR-SEC-03` の既知の制限）。XSS が起きるとトークンを盗まれる。HttpOnly Cookie と BFF（Next.js のサーバーを経由する方式）への変更が改善案だが、設計の変更になるため未着手。
- 他の画面（ダッシュボード、操作履歴）は未実装。カテゴリ、部品在庫、製品在庫は第 9 章。
- アカウント画面は無い。
- E2E テストは実バックエンドを使うため、CI では実行していない（ローカルでバックエンドを起動して実行する）。単体テスト、型検査、Lint、ビルドは CI で実行する。
- アクセストークンの有効期限（保留中）は変更していない。画面は、期限切れを自動で更新する前提で作ってある。

## 9. カテゴリ・部品在庫・製品在庫の画面

API は [detailed-design-stocks.md](detailed-design-stocks.md)。画面は原典の画面仕様（カテゴリ管理、部品在庫一覧、製品在庫一覧）に沿い、在庫センター画面と同じ操作（一覧、検索、並び替え、ページ送り、登録、編集、削除）を持つ。

### 9.1 共通の部品

- `usePagedList`（汎用の一覧フック）: 検索条件（絞り込み、ソート、ページ）と取得を管理する。古いリクエストの結果は破棄し、最後のページの最後の 1 件を削除して空になったときは 1 つ前のページへ戻る。
- `useCategoryOptions`、`useCenterOptions`: 検索条件と登録フォームの選択肢を、カテゴリ API とセンター API（名前の昇順、最大 100 件）から取る。部品在庫の選択肢は部品用のカテゴリだけ、製品在庫は製品用だけ。
- `Pagination`、`ConfirmDialog`（削除の確認）、`SortableTh`（`aria-sort` 付きの見出し）は画面で共有する。
- 部品在庫と製品在庫は同じ `StockListPage` を `kind`（`parts` / `products`）で切り替える。API のパス、列、製品コードの有無だけが違う。

### 9.2 カテゴリ管理（`/categories`）

| 項目 | 内容 |
| --- | --- |
| 検索 | カテゴリ種別（すべて / 部品 / 製品）、カテゴリ名（20 文字まで、部分一致） |
| 列 | カテゴリ種別（バッジ、並び替え可）、カテゴリ名（並び替え可）、説明（2 行まで）、操作（編集、削除） |
| 既定の並び | 種別の降順、カテゴリ名の降順（画面仕様どおり） |
| 登録・編集 | カテゴリ種別（必須）、カテゴリ名（必須、20 文字まで）、説明（任意、255 文字まで） |
| サーバーのエラー | 409（同じ種別の同名）は名前の欄に表示 |
| 削除 | 確認ダイアログ。**在庫で使用中のカテゴリは 400** で、トーストで通知する。使用中のカテゴリの種別変更も 400 で、モーダル上部に表示する |

### 9.3 部品在庫一覧（`/parts-stocks`）と製品在庫一覧（`/products-stocks`）

| 項目 | 部品在庫 | 製品在庫 |
| --- | --- | --- |
| 検索 | カテゴリ（選択）、名称（部分一致）、個数（以上・以下）、在庫センター（選択。画面仕様に無い追加） | 左に加えて製品コード（部分一致） |
| 列 | カテゴリ、名称、在庫数（個）、在庫センター、在庫説明、操作 | 製品コード、名称、カテゴリ、在庫数（個）、在庫センター、在庫説明、操作 |
| 並び替えできる列 | カテゴリ、名称、在庫数、在庫センター | 左に加えて製品コード |
| 既定の並び | カテゴリ名の昇順、名称の昇順（画面仕様の「カテゴリ/名称」） | 同じ |
| 登録・編集 | 名称、カテゴリ、在庫センター、在庫数（必須。0 以上 999,999,999 以下）、在庫説明（任意） | 左に加えて製品コード（必須、20 文字まで、半角英数字・ハイフン・アンダースコア） |

- カテゴリ名とセンター名は API が結合して返すため、画面で追加の呼び出しはしない。
- 同じ名称が別のセンターにあり得るため、操作ボタンのラベルは「名称（センター名）」にする（例: `LiPo 3S 2200mAh（東京センター）を編集`）。
- 個数（以上）が個数（以下）を超える検索は、API を呼ばずに画面でエラーを表示する。整数以外の入力も同様。
- サーバーのエラー: 409 は、製品コードの重複なら製品コードの欄、センター内の名称の重複なら名称の欄に表示する。400 でメッセージが項目名（カテゴリ、在庫センター など）で始まるものはその項目に、それ以外はモーダル上部に表示する。
- 削除済みの在庫を削除した（404）ときは成功として扱う。
- 在庫の一覧は、センターごとの在庫の確認に使える。センターの詳細画面（センターからの導線）は未実装。

### 9.4 横断検索（想定のみ）

部品と製品をまたいだ 1 つの検索結果は、現時点では作らない。必要になったら、バックエンドに 1 本の検索 API（`GET /api/v1/stocks/search`、[detailed-design-stocks.md](detailed-design-stocks.md) 第 9 章）を足して対応する想定である。画面から 2 つの API を別々に呼ぶ方式では、ページングを統合できない。
